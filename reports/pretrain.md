# 预训练 · d24

底座是自己训的，不是下载的官方权重。单张 RTX PRO 5000（48GB）从零训练 nanochat d24，训完再做读后续写。正式发布的是后训练权重；这一页只记预训练结束时的 `d24_core_attempt1` step 5568。后训练没有改结构，DPO v10 的层数、宽度、词表和这里相同。

Checkpoint 在本机 `~/.cache/nanochat/base_checkpoints/d24_core_attempt1/model_005568.pt`。仓库 `weights/` 里的分片是 DPO v10 的推理副本，不是这份底座。

## 结构

深度 24、宽高比 64，隐层因此是 1536。头维度按 128 对齐，得到 12 头。Query 和 Key/Value 头数相同，没有做分组查询。

| 项 | 值 |
|---|---|
| 层数 | 24 |
| 隐层 | 1536 |
| 头数 | 12（query 和 key/value 都是 12） |
| 每头维度 | 128 |
| 上下文 | 2048 |
| 词表 | 32768 |
| MLP | 1536 → 6144 → 1536，激活是 ReLU 再平方 |
| 注意力 | 每层全长窗口（`window_pattern=L`） |
| 位置 | RoPE，base 100000；没有绝对位置嵌入 |
| 输出 | logit 乘 tanh 软顶，softcap 15 |
| 归一化 | RMSNorm，无学习参数；注意力有 QK norm |
| 线性层 | 无 bias；词嵌入和 lm_head 不共享权重 |
| value embedding | 隔层一份，含最后一层，共 12 份，每份 32768×1536 |
| 标量 | 每层残差缩放、输入混合，另有 token smear 和 backout |

词表是在 ClimbMix 上用 rustbpe 训的 BPE，切分接近 GPT-4。`<|bos|>` 用来切开文档。`<|user_start|>` 这类对话符号在词表里，预训练的损失没见过它们，对话格式是 SFT 才学的。

## 参数量

训练开始时打印的计数：

| 部分 | 参数量 | 占总量 |
|---|---:|---:|
| 词嵌入 `wte` | 50,331,648 | 3.6% |
| value embeddings | 603,979,776 | 43.6% |
| `lm_head` | 50,331,648 | 3.6% |
| 注意力和 MLP 矩阵 | 679,478,976 | 49.1% |
| 标量 | 74 | — |
| **合计** | **1,384,122,122** | **100%** |

步数不按 13.84 亿来乘。nanochat 的数据比例只用「注意力和 MLP 矩阵 + lm_head」，这里是 **7.298 亿**。`target-param-data-ratio=8` 因此对应约 58.4 亿 token。value embedding 占了将近一半参数，但不进这个比例。

主权重用 bf16 计算。矩阵在优化器里保持更高精度，词嵌入和 value embedding 在初始化后转成 bf16，用来省显存。

## 训练配方

数据是 [ClimbMix-400B](https://huggingface.co/datasets/karpathy/climbmix-400b-shuffle) 打乱后的 parquet。最后一个分片做验证，其余做训练。跑完时数据加载停在第 1 遍的 shard 130，400B 没有走完。

优化器是 MuonAdamW：注意力和 MLP 用 Muon，嵌入、lm_head 和标量用 AdamW。学习率从 d12 的参考值迁过来。总批次从 524,288 加到 1,048,576，Adam/Muon 的学习率乘 √2；Adam 再按隐层从 768 加到 1536 乘 1/√2。这两步在词嵌入和 lm_head 上抵消，实际初始学习率就是命令行上的数。

| 参数 | 优化器 | 实际初始学习率 |
|---|---|---:|
| 词嵌入 | AdamW | 0.3 |
| lm_head | AdamW | 0.008 |
| value embedding | AdamW | 0.15 |
| 注意力和 MLP | Muon | 0.02828 |
| 输入混合标量 | AdamW | 0.707 |
| smear / backout | AdamW | 0.2 |

Muon 的权重衰减从参考值 0.28 缩到 **0.0597**，再按余弦降到 0。动量前 400 步从 0.85 升到 0.97，学习率下降段降到 0.90。学习率本身：前 40 步线性升温，大约保持到第 1949 步，之后线性降到初始值的 5%。

| 项 | 值 |
|---|---|
| 每卡微批次 | 8 条序列 × 2048 = 16,384 token |
| 梯度累积 | 64 |
| 总批次 | 1,048,576 token |
| 精度 | bf16，没有开 fp8 |
| 注意力实现 | PyTorch SDPA（这张卡没有 Flash Attention 3） |
| 验证 | 每 50 步，10,485,760 token 上的 bpb |
| CORE | 只在最后一步估一次，每项最多 500 例 |
| 速度 | 约 31,000 token/s，一步约 34 秒 |

这张 Blackwell 的峰值 FLOPS 没有写进 nanochat 的表，日志里的 MFU 一直是 0，不代表利用率真是 0。按模型自己的估计，每个 token 5.28×10^9 FLOPs。

## CORE

CORE 是 DCLM 的 22 项指标。每项先算准确率，再减掉该题的随机基线、除以「全对减随机」，得到 centered accuracy。CORE 是这 22 个 centered 的平均，随机是 0，全对是 1。

这次用的是训练脚本的默认抽样：每项打乱后最多 **500** 例，种子 1337。官方 time-to-GPT-2 在结束时跑的是全量（`core-metric-max-per-task=-1`）。0.2620 因此是估计，和 GPT-2 的 0.2565、Run 6 的 0.2626 同一把尺子，但方差比全量大。

## 这些数字对应的能力

预训练目标是网页和书籍风格文本的下一个 token。测到的强项是短上下文里的常识和句子收尾：PIQA 75%，ARC-Easy 72%，HellaSwag 约 56–58%，LAMBADA 45%，Winograd 66%。更难的推理弱：ARC-Challenge 42%，LSAT 逻辑题 27%，CommonsenseQA 24%。WinoGrande 只比随机高一截。BoolQ 的 centered 是负的，这项抽样上低于它自己的随机基线。精确照抄和括号匹配基本不会：repeat-copy 是 0，Dyck 语言是 12%。

上下文 2048 token。一道读后续写大约是 350 词原文加两句开头再加 150 词正文，放得下，不需要加长上下文。

这份底座不会做高考读后续写。它没有学过「只写两段、开头不能改」。情节前后一致要等 SFT 和 DPO，那些数字在 [summary.md](summary.md)。CORE 过了 GPT-2，说明通用短题到了这个量级；它不衡量「读完一篇记叙文再续写、还不许写反」。

## 单卡上改过的地方

官方配方在这张卡上跑不动，改了三处，模型尺寸和数据比例没改：

- depth 24，`target-param-data-ratio=8`（GPT-2 CORE 的欠训练配方）。把这个宽度喂饱的比例更高，项目没有再训一个更长的底座做对照。
- `device-batch-size=8`。16 在 48GB 上会 OOM，8 的峰值是 37,593 MiB。总批次仍是自动算出来的 1,048,576，靠 64 步梯度累积补齐。
- `window-pattern=L`。这张 Blackwell 没有 FA3，官方的短窗加长窗在 SDPA 上太慢，改成全长窗口。原文会留在注意力里，读后续写里的情节错误不能归因于窗口把前文截掉。
- 没有开 fp8。
